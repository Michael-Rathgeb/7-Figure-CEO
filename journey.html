Agent Deployer

From zero to your own always-on AI agent in one sitting

You open the folder in Claude Code or Codex and say “deploy an agent for me.” Your coding agent does the work in four stages. You answer questions, paste a couple of secrets, click a few login links, and send the first message. Roughly 45 minutes.

YouYour coding agentA gate: you review, then it continues

The four stages, close up

1 · Intake

~5 min
Coding agent
  • Asks which agent (Hermes or OpenClaw), which host (VPS or Mac mini), do you have a server yet, which brain, which chat channel, how you’ll reach the dashboard, Composio, backups.
  • Writes everything into answers.md. Unknowns stay unknown, never guessed.
You
  • Answer in your own words. Fetch the Telegram bot token while it works.
Gate: read answers.md, fix anything, say yes.

2 · Assemble

~5 min
Coding agent
  • Copies the right compose file, adds the pieces you chose (Tailscale, backups, Composio, a public domain).
  • Generates the dashboard password and gateway token.
  • Prepares the settings file with blanks for your secrets, and a README for you.
You
  • Paste your Telegram bot token and your id into the chat. It files them and never repeats them. You never open a config file or log into a server.
Gate: nothing left blank. It checks without reading the values back.

3 · Deploy

~25 min
Coding agent
  • No server? Buys one after you confirm the price.
  • Docker, SSH hardening, firewall, Tailscale on the host.
  • Copies the stack, pulls the image, runs onboarding and the provider login, starts it, sets autostart, takes a backup, installs Composio.
  • Logs every command and error in deploy-log.md.
You
  • Confirm the price. Enter one ChatGPT device code. Click the Tailscale and Composio links. Watch the first minute of logs.
Gate: you say “it’s up.”

4 · Verify

~5 min
Coding agent
  • Runs the checklist: services healthy, fresh image, no secrets in compose, ports private, dashboard demands login, survives a Docker restart, backup archive exists, the model answers a test prompt, chat channel connected.
  • Writes verify-report.md with evidence, and a one-page handoff sheet with your links and logins.
You
  • Open the dashboard URL. Message your bot from your phone.
Gate: the reply is the last line of the report. Done.

Have these ready

  • Claude Code or Codex, installed and signed in on your laptop.
  • An SSH key. The agent can make one, but have it before buying a server.
  • Somewhere to run it. A VPS with 4 GB or more on Ubuntu 24.04, an Apple Silicon Mac mini, or a Hostinger account with a card that works.
  • A brain. A ChatGPT Plus or Pro subscription (Hermes and OpenClaw both use it, no key), or an Anthropic, OpenAI, or OpenRouter key with billing set up.
  • A way to talk to it. A Telegram bot from @BotFather and your numeric id from @userinfobot. Or a Discord bot.
  • Tailscale account, with the app on the phone or laptop you’ll open the dashboard from. HTTPS and MagicDNS turned on once in the admin console.
  • Composio account, optional, for Gmail, Slack, Notion, GitHub and 1,500 more apps.
  • Your phone nearby. Three or four link approvals happen during deploy.

What you end up with

  • An agent that stays up. Restart policy set, comes back after a reboot, image refreshed on every update.
  • Private by default. Every port bound to localhost. The dashboard lives on your tailnet with a real certificate, or behind a domain with automatic TLS on a VPS. Nothing on the public IP.
  • Only you can talk to it. Chat allowlisted to your id. Adding a partner is one runbook.
  • Backups. Daily archive of the agent’s memory and keys, last 14 kept.
  • A handoff sheet with every link and login, and the workspace folder on your laptop holding every run’s answers, log and report. You never SSH or edit a config file.
  • Day two is covered. Say “update the agent”, “show me the logs”, “my ChatGPT login expired”, “let my assistant message it”, or “remove it”. Each is a runbook the coding agent follows.

Two agents are supported today: Hermes (Nous Research) and OpenClaw. Two hosts: a VPS and an Apple Silicon Mac mini. Every card in the workspace carries a “verified” date and a link to the upstream docs, and when the software disagrees with a card, the coding agent reads the docs, fixes the card, and keeps going.
